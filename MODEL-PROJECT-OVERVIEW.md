# Смысл Модельного проекта

## Схема процесса

```text
Проблема
   |
   v
Исследование -> Evidence
   |
   v
Проверяемая гипотеза
   |
   v
Малый MVP
   |
   v
Сигнал рынка
   |
   +--> Развивать
   |
   +--> Закрыть
```

## Структура файлов

```text
Модельный проект/
|
|-- PROJECT.md          # паспорт, границы, статус
|-- idea/               # проблема, гипотеза, MVP
|-- business/           # аудитория, экономика, маркетинг
|-- analysis/           # рабочие прогоны бизнес- и системного анализа
|-- research/           # evidence и исследования
|-- plans/              # планы разработки
|-- docs/analysis/      # требования, модели, ТЗ и review
|-- docs/decisions/     # принятые архитектурные решения
|-- knowledge/          # проверенные знания и источники
|-- mastery/            # методы работы
|-- retrospectives/     # история и выводы
`-- scripts/            # создание и проверка проектов
```

## Что за что отвечает и как работает

1. `PROJECT.md` задает цель и границы, а `idea/`, `business/` и `research/` проверяют, стоит ли делать продукт.
2. `analysis/runs/` хранит рабочий контекст аналитической задачи, а подтвержденные бизнес- и системные артефакты получают единственного владельца в `business/analysis/` или `docs/analysis/`.
3. `plans/` описывает работу, `docs/decisions/` хранит решения, `scripts/` создает проект и проверяет правила.
4. `knowledge/`, `mastery/` и `retrospectives/` сохраняют проверенные знания, методы и выводы для следующих шагов.

## Автонакопление памяти и база знаний

```text
Изменение файлов
       |
       v
knowledge-curator -> Есть новый устойчивый вывод?
                           | нет -> ничего
                           ` да -> knowledge/candidates/ (ready)
                                             |
                                      решение человека
                                             v
                              канонический файл <- backlink
```

- Автонакопление работает только в `active + safe-local` при наличии Git `HEAD`; автоматического promotion и удаления нет.
- Память проекта - это проверяемые Markdown-файлы и история Git, а не скрытая локальная память Codex.
- Wikilinks `[[...]]` можно использовать для Obsidian, но обязательными и каноническими остаются переносимые ссылки `[текст](путь)`.
